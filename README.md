# Shade Server

Shade — HTTP(S) reverse proxy с парольной аутентификацией. Один Gateway обслуживает два независимых веб-сайта: публичный доступен всем, приватный — пользователям с действующей сессией Shade. Для входа используется отдельное расширение Chromium **Shade Client**.

Сервер не содержит встроенных сайтов, не запускает браузер и не требует файлов конфигурации на стороне клиента. Версия протокола — 0.9; реализация OPAQUE ещё требует интеграционной проверки на целевой системе.

## Принцип работы

```text
Chromium + Shade Client
         │ HTTPS
         ▼
   Python Gateway ─── stdin/stdout ─── Node.js / OPAQUE
         │
         ├── без действующей сессии ──► публичный backend
         └── действующая сессия ───────► приватный backend
```

### Авторизация

- Администратор локально задаёт пароль. `@serenity-kit/opaque` формирует серверные параметры и регистрационную запись; сам пароль не сохраняется. Удалённой регистрации нет.
- Расширение начинает обмен OPAQUE сообщением KE1 (`POST /.well-known/shade-opaque/start`). Gateway возвращает KE2 и случайный идентификатор попытки. Состояние попытки хранится в памяти до 30 секунд, одновременно допускается не более 256 ожидающих попыток.
- Клиент проверяет KE2 с использованием введённого пароля. Если пароль правильный, он формирует KE3 и отправляет его на `POST /.well-known/shade-opaque/finish`. Сервер потребляет состояние попытки один раз. Только после проверки KE3 выдаётся случайный 256-битный сессионный токен. Пароль и его постоянный хеш по сети не передаются.
- Расширение устанавливает токен в HttpOnly cookie (`Secure` для HTTPS, `SameSite=Lax`, путь `/`). Gateway хранит SHA-256 токена в памяти и проверяет срок действия (по умолчанию 30 минут). Выход отзывает токен, перезапуск удаляет все сессии. Подписывать каждый запрос не требуется.

При неверном пароле расширение открывает обычную публичную страницу. Некорректные сообщения на маршрутах авторизации обрабатываются Gateway через публичную главную страницу вместо специального ответа с ошибкой пароля. Валидное KE1 всё равно получает KE2: абсолютная неотличимость от обычного сайта не гарантируется.

### Маршрутизация

Gateway принимает HTTP(S)-запрос, проверяет сессионную cookie и, для изменяющих состояние методов, соответствие `Origin`. Затем через `aiohttp` пересылает запрос на один из двух фиксированных upstream-адресов. Метод, путь, параметры и тело сохраняются, за исключением служебных запросов и отдельных случаев отклонённой приватной авторизации. Служебные заголовки и cookie Shade не передаются backend. Gateway не накапливает cookies backend в общем клиентском хранилище. Ответ возвращается через тот же публичный адрес; редиректы на адрес выбранного backend переписываются на публичный URL. Кэширование ответов отключено.

### Технологии

Python 3.10+, `aiohttp`, `yarl`, стандартный модуль `ssl`; Node.js 22+ и `@serenity-kit/opaque@1.1.0` (WebAssembly). Python запускает локальный криптографический процесс через stdin/stdout без отдельного сетевого сервера. Допускается не более четырёх параллельных криптографических вызовов, таймаут — 20 секунд. На попытки входа действует базовый лимит 20 запросов на IP в минуту (с учётом того, что ограничитель применяется к обоим POST-маршрутам авторизации). Прямой HTTPS или внешний TLS-прокси поддерживаются штатно.

## Установка

### 1. Подготовка

Понадобятся Linux, Python 3.10 или новее с `venv` и `pip`, Node.js 22 или новее, npm, а также два самостоятельно развёрнутых HTTP(S)-сайта. Доступ к npm и PyPI нужен на этапе установки.

Arch Linux / CachyOS:

```bash
sudo pacman -S --needed python python-pip nodejs npm
```

На других дистрибутивах установите перечисленные зависимости штатным пакетным менеджером и проверьте версии:

```bash
python3 --version
node --version
npm --version
```

### 2. Установка зависимостей Shade

Распакуйте исходники или скачайте этот репозиторий и откройте его корневую папку (`shade-server`). Выполните:

```bash
bash install.sh
```

Скрипт создаёт локальное окружение `.venv`, устанавливает Python- и npm-зависимости, проверяет импорт модулей и запускает реальный локальный тест OPAQUE на случайном пароле (успешная авторизация, отклонение неверного пароля и некорректного KE3). Системный Python не изменяется. Конфигурация сервера и пользовательский пароль не затрагиваются. При повторной установке используется существующее окружение; при наличии `package-lock.json` применяется `npm ci`.

Вручную (если не нужен установочный скрипт):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm install --omit=dev
node tools/check-opaque.mjs
```

### 3. Первый запуск и настройка

```bash
.venv/bin/python server.py
```

Если конфигурации нет, откроется мастер. Он спросит:

| Параметр | Что указать |
| --- | --- |
| Public backend | URL существующего публичного сайта, например `http://127.0.0.1:9001` |
| Hidden backend | URL существующего приватного сайта, например `http://127.0.0.1:9002` |
| Gateway bind IP | IP для прослушивания, например `127.0.0.1` |
| Gateway listen port | Порт самого Gateway, например `8080` |
| HTTPS | `off`, `direct` или `reverse_proxy` |
| PUBLIC URL | Адрес Gateway, который будет вводиться в расширении |
| Password | Длинный пароль, не менее 12 символов, с подтверждением |

Примеры локальных адресов приведены для иллюстрации: Shade не создаёт сайты на портах 9001 и 9002. Backend должны уже работать. URL backend указывается без пути, параметров, логина и пароля.

При локальной проверке выберите `off`, bind `127.0.0.1`, порт `8080`, публичный URL `http://127.0.0.1:8080`. Запустите Gateway, откройте этот URL в браузере без подключения Shade, затем проверьте вход через расширение.

Мастер создаст `server/config.json` с правами `0600`. При последующих интерактивных запусках можно принять сохранённые параметры клавишей Enter или изменить их через `c`. Для отдельной настройки без запуска используйте `configure`.

### 4. HTTPS

**`off`**: HTTP разрешён только на loopback; для удалённых пользователей необходим HTTPS.

**`direct`**: Gateway принимает TLS самостоятельно. Выберите режим `direct`, укажите IP (например `0.0.0.0`), порт (например `8443`), пути к настоящему PEM-сертификату (полная цепочка) и закрытому ключу, а также точный внешний HTTPS URL с портом, если он отличается от 443. Сертификат должен быть доверенным браузером и соответствовать доменному имени. Проверка файлов: `.venv/bin/python server.py check`. Для порта 443 используйте корректно настроенный внешний прокси или системные права на порт, не запускайте весь Gateway от root без необходимости.

**`reverse_proxy`**: TLS завершает отдельный доверенный прокси (например Caddy). Настройте Gateway на `127.0.0.1:8080`, режим `reverse_proxy`, публичный URL `https://shade.example.com` (замените пример своим доменом). Пример блока для уже установленного Caddy:

```caddyfile
shade.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Настройте DNS своего домена и откройте нужные порты прокси. Не публикуйте внутренний порт Gateway и приватный backend. Внешний прокси должен сохранять исходный Host (и не кэшировать ответы). Caddy при подходящей конфигурации сам получает и обновляет сертификаты. Не отключайте проверку TLS в клиенте.

### 5. Управление

Команды выполняются из корня проекта. Активация виртуального окружения не требуется.

| Команда | Действие |
| --- | --- |
| `.venv/bin/python server.py` | Запуск в терминале |
| `.venv/bin/python server.py configure` | Изменение сетевой конфигурации |
| `.venv/bin/python server.py set-password` | Новая локальная регистрация пароля |
| `.venv/bin/python server.py check` | Проверка конфигурации, TLS и загрузки OPAQUE |
| `.venv/bin/python server.py restart` | SIGHUP работающему процессу: перечитывает конфиг, сбрасывает сессии |
| `.venv/bin/python server.py stop` | Остановка процесса |

`restart` не запускает остановленный сервер. Если меняли параметры через `configure` при работающем Gateway, выполните `restart`. Смена пароля сама отправляет сигнал работающему процессу. После изменения проверьте сообщения запущенного сервера и вход клиента. Ctrl+C также останавливает Gateway. Для постоянной работы используйте свой менеджер служб; скрипт установки не устанавливает systemd-службу.

### 6. Конфигурация и обновление

`server/config.json` содержит `gateway` (bind, порт, публичный URL и TLS), `backends` (публичный и приватный upstream), `auth` (серверная OPAQUE-запись), `limits` (размер запроса, таймаут upstream, срок сессии). Не публикуйте этот файл и приватные ключи TLS. Они исключены из Git; при резервном копировании защищайте их как секреты.

При обновлении Shade 0.9 остановите старый Gateway, сохраните его `server/config.json`, перенесите его в новый `server/` и повторите `bash install.sh`. Для совместимой конфигурации `serenity-opaque-1.1.0` новый пароль не нужен. Для 0.7/0.8 после переноса файла выполните `set-password`, чтобы зарегистрировать пароль в текущей библиотеке. При переносе относительных путей к TLS-файлам проверьте их доступность. Затем `check` и запуск. У клиента и сервера должна быть одна версия протокола.

## Ограничения безопасности

- Это MVP, не прошедший независимый криптографический аудит. Версия OPAQUE зафиксирована, но соответствие финальному RFC 9807 не подтверждено. При подготовке этих исходников npm был недоступен: реальный обмен необходимо проверить установочным самотестом и затем расширением.
- Оба сайта используют один browser origin: недоверенный JavaScript публичного сайта может обратиться к приватным ресурсам после входа. Публичный backend должен быть доверенным. Cookie не изолированы по портам.
- OPAQUE защищает от пассивного офлайн-подбора по перехваченному корректному обмену, но не от онлайн-перебора, компрометации устройства, украденной cookie или всех сценариев кражи серверной записи. Лимитер локален для одного процесса; за TLS-прокси он может считать всех пользователей одним IP.
- Даже при неудачной авторизации публичный backend должен быть доступен; его сбой может привести к `502`. Отличия в поведении служебных маршрутов обнаружимы.
- Нужна изоляция приватного backend от прямого доступа. WebSocket и потоковое проксирование пока не поддерживаются; ответы буферизуются. На страницах ограничена регистрация новых Service Worker и встраивание во фреймы.
