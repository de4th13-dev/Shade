# Shade Server

HTTP(S) reverse proxy для двух веб-сайтов на одном внешнем адресе. Публичный сайт доступен без авторизации, приватный — через действующую сессию Shade. Для входа используется расширение Shade Client.

## Принцип работы

```text
Клиент ── HTTP(S) ── Shade Gateway
                         ├── без сессии → публичный backend
                         └── с сессией  → приватный backend
```

Администратор задаёт пароль локально. Сервер хранит регистрационную запись OPAQUE, а не пароль. При входе клиент и сервер обмениваются сообщениями KE1, KE2 и KE3; после успешной проверки сервер выдаёт случайный сессионный токен. Расширение сохраняет его в HttpOnly cookie (`Secure` при HTTPS). Сессия по умолчанию действует 30 минут и отзывается при выходе или перезапуске сервера.

Gateway определяет текущий origin по заголовку `Host` и выбранному режиму TLS. Фиксированный внешний URL не требуется. Сессии и незавершённые попытки входа привязаны к этому origin. Gateway проверяет сессию и `Origin` для изменяющих состояние запросов. Для HTML-форм с `Origin: null` допускается только POST с браузерными Fetch Metadata, подтверждающими навигацию с того же origin. При действующей сессии и неверном origin возвращается 403 без передачи запроса backend. Запрос передаётся выбранному backend с методом, путём, параметрами и телом; служебные данные Shade удаляются. Ответ возвращается через исходный адрес Gateway. Неуспешный вход не предоставляет приватный доступ.

Сервер использует Python (`aiohttp`, `yarl`, `ssl`) и `@serenity-kit/opaque` 1.1.0 через локальный Node.js-процесс. Отдельный сетевой криптографический сервис не нужен.

## Установка

### Требования

- Linux с Bash (другие ОС не проверены).
- Python 3.10+ с модулями `venv` и `pip`.
- Node.js 22+ и npm.
- Два уже работающих HTTP(S)-сайта: публичный и приватный.
- Для доступа через интернет — доменное имя и доверенный TLS-сертификат или внешний HTTPS-прокси.

Установите системные зависимости средствами своего дистрибутива. Скачайте исходники из репозитория, распакуйте их и откройте корневую папку проекта в терминале.

```sh
bash install.sh
```

Скрипт создаст `.venv`, установит зависимости и выполнит самотест OPAQUE. Настройки и пароль не изменяются.

### Первый запуск

```sh
.venv/bin/python server.py
```

При первом запуске мастер предложит указать параметры:

| Поле | Значение |
| --- | --- |
| Public backend | HTTP(S)-адрес публичного сайта |
| Hidden backend | HTTP(S)-адрес приватного сайта |
| Gateway bind IP | IP-адрес, на котором слушает Gateway |
| Gateway listen port | Порт Gateway |
| HTTPS | `off`, `direct` или `reverse_proxy` |
| Password | Пароль (от 12 символов) |

Адреса backend указываются без пути, параметров и учётных данных. Shade не запускает эти сайты самостоятельно. Не указывайте адрес Gateway или внешний прокси, ведущий обратно к нему, как backend: это создаст цикл проксирования.

Конфигурация сохраняется в `server/config.json`. При следующих запусках можно принять текущие настройки или изменить их.

### HTTPS

| Режим | Назначение |
| --- | --- |
| `off` | HTTP только на loopback для локальной разработки |
| `direct` | Gateway принимает HTTPS; укажите пути к PEM-сертификату и закрытому ключу |
| `reverse_proxy` | HTTPS принимает внешний прокси, Gateway слушает loopback |

Пример настройки Caddy при режиме `reverse_proxy`:

```caddyfile
shade.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Замените домен и порт на фактические. В конфигурации Shade укажите `127.0.0.1`, внутренний порт Gateway и режим `reverse_proxy`. Внешний прокси должен сохранять исходный `Host` (включая нестандартный порт), проверять разрешённые домены и не допускать прямого доступа к Gateway. Настройте DNS и TLS на прокси. Не публикуйте внутренний порт Gateway и приватный backend.

### Управление

Команды выполняются из корня проекта. Активировать виртуальное окружение не требуется.

| Команда | Действие |
| --- | --- |
| `.venv/bin/python server.py` | Запуск |
| `.venv/bin/python server.py configure` | Настройка адресов, портов и TLS |
| `.venv/bin/python server.py set-password` | Смена пароля |
| `.venv/bin/python server.py check` | Проверка конфигурации и зависимостей |
| `.venv/bin/python server.py restart` | Перечитать конфигурацию работающего процесса |
| `.venv/bin/python server.py stop` | Остановка |

После изменения сетевых настроек выполните `restart`. Смена пароля перезапускает работающий Gateway. Все сессии при перезапуске сбрасываются. Для постоянной работы настройте менеджер служб самостоятельно.

### Обновление

Остановите Gateway, сохраните `server/config.json` и TLS-ключи. Замените исходники, повторите `bash install.sh`, проверьте конфигурацию командой `check` и запустите сервер. При миграции со старой парольной схемы выполните `set-password`. Старое поле `gateway.public_url` игнорируется и удаляется при следующем сохранении настроек.

## Ограничения

- Проект находится на стадии MVP, независимый аудит безопасности не проводился. Совместимость реального обмена OPAQUE и соответствие финальному RFC 9807 требуют проверки.
- Публичный и приватный сайты имеют общий origin. Публичный backend должен быть доверенным: его JavaScript может обращаться к приватным ресурсам при активной сессии.
- Сессия является ключом доступа до истечения или отзыва. Cookie не изолированы по портам. Не публикуйте `server/config.json` и закрытые ключи TLS.
- WebSocket и потоковое проксирование не поддерживаются. Ответы буферизуются. Служебные маршруты авторизации могут быть обнаружены.
